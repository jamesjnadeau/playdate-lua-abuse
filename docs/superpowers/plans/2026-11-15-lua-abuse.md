# playdate-lua-abuse Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Playdate Lua game with one mode per performance sin, plus a check script proving the Playdate Performance Simulator (pdsim) blames each mode on the right cause.

**Architecture:** `Source/main.lua` owns the menu, auto-cycle and `config.json` mode selection; each mode is a self-contained table in `Source/modes/<id>.lua`. `tools/check.py` runs pdsim once per mode with a fresh data dir and evaluates `tools/expectations.json` against the report and per-frame JSONL.

**Tech Stack:** Lua 5.4 (Playdate dialect, CoreLibs from SDK 3.1.2), Python 3 stdlib (`unittest`), pdsim at `../playdate-performance-simulator`.

**Spec:** `docs/superpowers/specs/2026-11-15-lua-abuse-design.md`

## Global Constraints

- Must build with `pdc` and run unchanged on device and in pdsim; draw everything procedurally (no image/font assets).
- SDK: `PLAYDATE_SDK_PATH`, else `~/Developer/PlaydateSDK-3.1.2`; `check.py` fails (exit 2) if neither exists — never fall back to pdsim stand-ins.
- pdsim: `$PDSIM_DIR`, default `../playdate-performance-simulator`; use `target/release/pdsim` if present, else `cargo run --release -p pdsim-cli --` from that dir.
- Checks run on pdsim's built-in estimates; `--calibration <file>` only passed through.
- Assertions are relative only (dominant category, top hotspot regex, over-budget fraction, spike grouping) — never absolute ms/cycles.
- Warm-up: first 10 frames (0-based `index`) ignored by every expectation. Default run: 300 frames.
- The game never writes `config.json`; `disk` mode writes `abuse-disk` only.
- Mode ids: `control garbage hotloop overdraw sprites disk spike`; config `{"mode": "<id>"}` or `{"mode": "auto", "cycleFrames": N}` (default 300). Unknown/missing → menu.
- Each mode's intensity is a constant at the top of its file, tuned to be clearly (not absurdly, ≲10×) over budget.
- Python: stdlib only. Output dir `out/` is git-ignored.

## Review Focus

1. **A Lua error mid-run** — pdsim stops early (`report.frames` < requested); check must FAIL that mode with "game stopped at frame N", not evaluate a short run. (Task 2 test)
2. **Unknown mode id in config** — game shows the menu and runs all frames without error. (Task 1 verification)
3. **`disk` mode clobbering `config.json`** — after a `disk` run, the data dir's `config.json` still says `disk`. (Task 7 check)
4. **Mode teardown leaking into the next mode** — in auto-cycle, `control` frames after `sprites`/`garbage` must be under budget again. (Task 9 check)
5. **SDK or pdsim missing** — clear message and exit 2, not a Python traceback. (Task 3 test)

### Task 2: `check.py` evaluation core (pure functions, TDD)

**Files:**
- Create: `tools/check.py`, `tools/test_check.py`

**Interfaces:**
- Produces (in `tools/check.py`):
  - `post_warmup(frames: list[dict], warmup: int) -> list[dict]` — frames with `index >= warmup`.
  - `dominant_category(frames: list[dict], exclude: list[str]) -> str` — category with the largest summed `categories[...]` ms.
  - `over_budget_fraction(frames: list[dict]) -> float`
  - `spike_groups(frames: list[dict]) -> list[list[int]]` — over-budget indices grouped into runs of consecutive indices.
  - `evaluate(expect: dict, report: dict, frames: list[dict], requested: int, warmup: int) -> list[str]` — failure messages; `[]` = pass.
- Expectation keys: `dominant_category` (str), `dominant_exclude` (list, default `["display"]`), `top_hotspot_matches` (regex vs `report["hotspots"][0]["name"]`), `over_budget` (bool: true ⇒ fraction > 0.5, false ⇒ zero over-budget frames), `spike_period` (int P ⇒ ≥3 groups, each ≤3 frames long, consecutive group starts ≥ P−5 apart, and no over-budget frames outside groups), `avg_rows_updated_min` (number vs mean `rows_updated`).

- [ ] **Step 1: Write failing tests** in `tools/test_check.py` (`unittest`), building frames with a helper `f(i, over=False, rows=240, **cats)`:
  - `test_post_warmup_drops_first_frames`: indices 0..14, warmup 10 → indices 10..14.
  - `test_dominant_excludes_display`: display 5, gc 2, lua 1 each frame → `"gc"`.
  - `test_over_budget_true_needs_majority`: 6 of 10 over → passes `{"over_budget": True}`; 5 of 10 → one failure.
  - `test_over_budget_false_needs_zero`: one over → failure mentioning its index.
  - `test_spike_groups_pass`: over at 60,61,120,180,240 (300 frames) with `{"spike_period": 60}` → `[]`.
  - `test_spike_groups_fail_extra_frame`: same plus 90 → failure.
  - `test_spike_groups_fail_too_few`: over at 60,120 → failure.
  - `test_top_hotspot_regex`: hotspots `[{"name":"loop hotloop.lua:12"}]`, `{"top_hotspot_matches": "hotloop\\.lua"}` → `[]`; `"^\\[graphics"` → failure naming the actual hotspot.
  - `test_rows_updated_min`: mean 200 vs min 230 → failure.
  - `test_short_run_fails` (Review Focus 1): `report["frames"] = 120`, requested 300 → `["game stopped at frame 120 of 300"]` and no other checks evaluated.
